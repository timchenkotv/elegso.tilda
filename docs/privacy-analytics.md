# Внешние подключения и согласие на аналитику

## Архитектура

- `config/site-privacy.json` — единственный разрешённый провайдер: Яндекс Метрика, счётчик 87831358. Поведенческие параметры выключены, аналитика по умолчанию запрещена.
- `scripts/privacy-analytics.mjs` — идемпотентная очистка старых подключений и установка общего загрузчика. По умолчанию только инвентаризация; изменение HTML требует `--apply`.
- `www/assets/site-privacy.js` — немодальная панель, явный выбор, настройки и отзыв. Закрытие панели и Escape не считаются согласием.
- `www/assets/site-privacy.css` — адаптивная панель без перекрывающей весь экран подложки; в печати скрыта.
- `www/assets/site-fonts.css`, `www/assets/fonts/` — локальные неизменённые Ubuntu и Prata с исходными лицензиями. Посетитель не обращается к Google Fonts.
- `ops/seo-admin/privacy_consent.py` — изолированная серверная запись выбора через `POST /api/privacy/consent`, без открытия доступа к административным API.
- `scripts/finalize-site.mjs` применяет очистку после генерации. Статьи и оферты наследуют чистую шапку из `www/mission/index.html`; издатель кейсов больше не вставляет Google Fonts.

Кнопка в общем подвале открывает настройки через атрибут `data-elegso-cookie-settings`. Никаких форм имени, телефона или email эта панель не создаёт. Политика — `/soglashenie/`, сведения о cookie — `/cookies/`, отдельное согласие на аналитику — `/consent/`.

## Поведение

До положительного выбора, после отказа, при истёкшей/неизвестной версии выбора и при недоступности сохранённого состояния `tag.js` и пиксели Яндекса не загружаются. Старые `noscript`-пиксели удалены: без JavaScript аналитика выключена.

При разрешении загружается только `https://mc.yandex.ru/metrika/tag.js`. Инициализация выполняется после загрузки, с проверкой, что согласие не отозвано за время запроса. `defer:true` предотвращает автоматический просмотр; один явный `hit` получает адрес страницы и реферер без query/hash. Значения калькуляторов, контактные данные и идентификаторы пользователей в параметры не добавляются. Отключены Вебвизор, карты кликов/ссылок, точный показатель отказов, отслеживание hash, iframe и ecommerce.

Выбор хранится 180 дней в `localStorage`, ключ `elegso.cookie-preferences.v1`: версия, обязательное хранение, аналитика, время выбора и истечения, случайный UUID события выбора (`choiceId`) и серверная квитанция (`receipt`). Запись не содержит ФИО, телефона, IP или URL. При недоступном хранилище подтверждённый сервером выбор действует только в текущей вкладке; при следующем посещении требуется повторный выбор.

До включения Метрики браузер отправляет на наш сервер ровно три поля: `choice_id`, `version`, `analytics`. Положительное согласие действует для загрузчика только после успешной записи и ответа сервера. Ошибка/таймаут (8 секунд) оставляет аналитику выключенной и показывает понятное сообщение; повторная попытка возможна вручную. Отказ сохраняется локально и выключает Метрику немедленно независимо от доставки квитанции.

Отзыв немедленно вызывает документированный метод `ym(87831358, 'destruct')`, препятствует поздней инициализации загрузчика и удаляет доступные текущему сайту аналитические cookie и адресные `_ym_`-ключи локального/сессионного хранилища. Настройка синхронизируется между вкладками через событие `storage`. Данные и идентификаторы калькуляторов не очищаются; принудительной перезагрузки страницы нет. Повторное согласие после отзыва получает новый случайный UUID: старую отозванную квитанцию сервер повторно не активирует.

## Серверные квитанции

Отдельная база `/var/lib/elegso-seo-admin/access/privacy-consent.sqlite3` (права `0600`) содержит только `choice_id`, `consent_version`, `analytics`, `recorded_at`, `expires_at`, `retain_until`. Срок хранения события — 365 дней от его первоначальной записи; повторная доставка того же выбора не продлевает время. Данные подтверждают событие выбора браузера, а не личность человека и не электронную подпись. Сама запись не подтверждает неизменность или достоверность всех сведений клиента.

Точный публичный маршрут принимает только JSON до 1 КиБ с каноническим UUIDv4, строгим boolean и известной версией согласия; Origin должен строго совпадать с `https://elegso.ru`. Старую версию можно отозвать, но нельзя заново разрешить. Лишние/повторяющиеся поля, отсутствующий Origin, query и некорректные типы отклоняются. Не принимаются и не записываются ФИО, IP, User-Agent, Referer или URL. Все данные в SQL передаются параметрами; подтверждение выдаётся только после транзакционного commit. Внутренние пути БД и SQL в ошибки не попадают.

Nginx не пишет access/error-журнал данного маршрута и не передаёт backend заголовки IP, User-Agent, Referer, авторизации и администратора. Отдельное глобальное ограничение 5 запросов/сек. с burst 20 учитывает архитектуру общего входящего edge-IP VM 240; идентификаторы посетителей не используются как ключ лимита. Это не защита от всех видов злоупотребления публичным API. Журналы внешнего TLS-прокси и резервные копии требуют отдельного контроля со стороны администратора.

`elegso-privacy-prune.timer` запускает ежедневное удаление просроченных событий только из privacy-таблицы, не затрагивая пользователей, SEO, посещения и расчёты. Из-за ежедневного расписания физическое удаление происходит в ближайший запуск после истечения срока (обычно до суток). `ops/hooks/post-receive` устанавливает модуль и обе units; root перед публикацией должен обновить фактический bare-repo hook, затем проверить timer и backend. Изменение версии согласия требует синхронного обновления `config/site-privacy.json` и `CURRENT_VERSION` сервера (или `PRIVACY_CONSENT_VERSION` в окружении); тест проверяет совпадение штатных значений.

## Границы гарантий

- Запись в `localStorage` можно удалить или изменить. Серверная квитанция усиливает подтверждение факта события, но не устанавливает личность, не является ЭП и не гарантирует защиту от намеренного изменения клиентского кода. Положительная квитанция не перепроверяется отдельным серверным запросом при каждом открытии страницы.
- Код страницы не может стереть HttpOnly-cookie, cookie доменов Яндекса/других провайдеров или уже переданные данные. Очистка браузера и обращение к оператору — отдельные действия.
- Запрос, начавшийся до отзыва, браузер не всегда позволяет гарантированно отменить. Новая инициализация после отзыва блокируется.
- Проверены параметры клиентского кода. Личный кабинет Метрики, автоматические цели, связанные рекламные кабинеты, роли, сроки хранения и настройки интеграций отдельно не проверялись. Это не утверждение о полной юридической достаточности настроек сервиса.
- При отказах охват статистики Метрики закономерно уменьшается. Собственные SEO-сводки, Яндекс Вебмастер, история поисковых позиций и backend мониторинга не удаляются.

## Проверка и сборка

```sh
node scripts/privacy-analytics.mjs --report reports/privacy-external-current.json
node scripts/privacy-analytics.mjs --apply
node --test tests/privacy-analytics.test.mjs tests/test_contact_popups.mjs tests/offers-navigation.test.mjs
python3 -m unittest discover -s tests -p test_case_publisher.py -q
python3 -m unittest discover -s tests -p test_privacy_consent.py -q
python3 -m unittest discover -s tests -p test_seo_admin.py -q
```

После сборки новых страниц повторить `--apply`; операция не меняет тексты документов и ссылок на правовые источники. Версия CSS/JS рассчитывается по содержимому и конфигурации. Для браузерной проверки открыть свежий профиль: до выбора не должно быть запросов Google, Mail.ru, Tilda-stat или Метрики; после положительного выбора допустима Метрика; после отказа/отзыва новая загрузка счётчика запрещена.
